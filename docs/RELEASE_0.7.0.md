# Nexus Shell 0.7.0

## Надёжная релизная упаковка

- Установщик и исполняемый файл получают одну версию `0.7.0` из параметра
  сборки.
- Имя установщика включает версию:
  `NexusShell-Setup-0.7.0-x64.exe`.
- Перед упаковкой обязательно запускаются текущие консольные проверки
  `Nexus.Core.Tests`.
- Publish проверяется на наличие приложения, XBF/PRI-ресурсов, .NET runtime,
  WinUI и self-contained Windows App Runtime.
- `runtimeconfig.json` и `deps.json` дополнительно подтверждают включённые
  `Microsoft.NETCore.App`, `Microsoft.WindowsDesktop.App` и RID `win-x64`.
- Сборка останавливается при несовпадении версии приложения или установщика.

## Обновление и удаление

- Установка остаётся строго пользовательской и не предлагает переход в
  административный режим.
- Каждый релиз размещает payload в отдельной папке вида
  `%LocalAppData%\Programs\Nexus Shell\app-0.7.0`.
- В каждый payload записывается `.nexus-shell-payload` с идентификатором
  продукта, версией и именем исполняемого файла.
- Ярлыки меню «Пуск», рабочего стола и автозапуска всегда указывают на payload
  текущей версии.
- Старый payload удаляется только на этапе `ssPostInstall`, когда файлы новой
  версии уже установлены и его маркер успешно проверен.
- Автоматически удаляется только прямой дочерний каталог `app-X.Y.Z`, если его
  маркер принадлежит Nexus, версия маркера совпадает с именем каталога и внутри
  есть `Nexus.App.exe`.
- Символические ссылки, junction и другие reparse-point каталоги очистка
  пропускает.
- Каталоги `app-*` без валидного маркера никогда не удаляются, в том числе при
  пользовательском `InstallLocation`.
- Прежняя плоская структура 0.6.0 распознаётся, но намеренно сохраняется:
  у неё нет надёжного маркера владения, поэтому безопасно отличить все её
  runtime-файлы от посторонних нельзя. Миграция заключается в установке нового
  versioned payload и переключении ярлыков на него.
- Если пользователь снимает выбор ярлыка рабочего стола или автозапуска,
  установщик удаляет только соответствующий точный ярлык `Nexus Shell.lnk`
  после успешной проверки нового payload.

## Контроль целостности

После успешной сборки в `outputs` создаются:

- `NexusShell-Setup-0.7.0-x64.exe`;
- `NexusShell-Setup-0.7.0-x64.sha256`;
- `NexusShell-Setup-0.7.0-x64.manifest.json`;
- `NexusShell-Setup-0.7.0-x64.manifest.txt`.

Манифесты содержат версию, архитектуру, Runtime Identifier, версию .NET SDK,
дату UTC, количество и размер файлов publish, размер установщика, SHA-256 и
состояние подписей. Схема 2 также записывает имя и маркер payload, политику
очистки, результат проверки self-contained и результат безустановочной
распаковки.

Если `innounp.exe` явно передан параметром, установлен в пользовательское
расположение или доступен через `PATH`, после компиляции установщик
распаковывается во временный каталог внутри `work`, не запускается и не
устанавливается. Бинарники из папки проекта автоматически не исполняются.
Проверяются единственный marker, каталог `app-X.Y.Z` и `Nexus.App.exe`, после
чего временный каталог удаляется. При отсутствии `innounp.exe` манифест получает
`SKIPPED_UNPACKER_NOT_FOUND`; это не выдаётся за пройденный smoke-тест.

## Цифровая подпись

По умолчанию сборка не пытается получить сертификат и явно записывает
`UNSIGNED` в оба манифеста.

Подпись включается только явным параметром `-SignInstaller` вместе с
40-символьным thumbprint сертификата из `CurrentUser\My`. Скрипт проверяет:

- наличие закрытого ключа;
- срок действия;
- назначение Code Signing;
- результат Authenticode после подписи.

Подписываются `Nexus.App.exe` перед упаковкой и готовый установщик после
компиляции Inno Setup. Пароль или закрытый ключ в проект не записываются.

## Команды

Обычная релизная сборка с восстановлением и аудитом пакетов:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File installer\build-installer.ps1
```

Только статическая проверка installer-safety, без publish, компиляции,
установки и удаления:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File installer\build-installer.ps1 `
  -ValidateOnly
```

Безустановочная проверка содержимого с явно указанным распаковщиком:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File installer\build-installer.ps1 `
  -InnoUnpackerPath "C:\Tools\innounp.exe"
```

Сборка с уже восстановленным локальным NuGet-кэшем:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File installer\build-installer.ps1 `
  -NoRestore
```

Подписанная сборка:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File installer\build-installer.ps1 `
  -SignInstaller `
  -CertificateThumbprint "0123456789ABCDEF0123456789ABCDEF01234567"
```

## Статус проверки

Сценарий PowerShell проходит разбор Windows PowerShell 5.1 и режим
`-ValidateOnly`. Статическая проверка подтверждает marker-gate перед
единственным рекурсивным удалением и versioned-цели всех трёх ярлыков.

Файл `outputs\NexusShell-Setup-0.7.0-x64.exe` от 29.07.2026 был собран до
этого усиления безопасности и не считается пересобранным hardened-артефактом.
В этой правке полная публикация, компиляция Inno Setup, распаковка, установка,
обновление и удаление не запускались. Текущая установленная версия 0.6.0 не
изменялась и не удалялась.
